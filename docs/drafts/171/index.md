# UI の状態 — 完成の絵に写らない画面を数える

## 今日のゴール

- 画面は 1 枚の絵ではなく、状況で変わる状態の集合だと知る
- その状態を UI Stack という 5 つの型で数える見方を知る
- 完成の前に、空・読み込み中・エラーが抜けていないか数える習慣を持つ

## 完成したはずの画面

Figma でタスク一覧の画面をきれいに作り上げたとします。カードが整然と並び、余白も揃った、完成度の高い 1 枚です。

でもこの 1 枚は、いくつもの前提の上に成り立っています。データがちょうどよく入っていて、通信も成功して、件数も多すぎず少なすぎない、という「**うまくいったとき**」の姿です。

この画面は、データが 0 件のとき・読み込んでいる最中・通信に失敗したときに、それぞれどう見えるでしょうか。

## 1 つの画面が取るいくつもの姿

タスク一覧を開いてから表示されるまでを、順番に追ってみます。

1. **開いた瞬間**: データはまだサーバーから届いていない。並べるものがない
2. **データが届いた**: カードが並ぶ。これがデザイン通りの姿
3. **でも 0 件だった**: 届いたけれど中身が空。画面には何も出ない
4. **通信が失敗した**: そもそもデータが取れない

同じ「タスク一覧」という 1 つの画面が、状況しだいで別の姿になります。デザインカンプが描いていたのは、このうち 2 番目の「データが届いた」だけです。

## UI Stack — 画面の 5 つの状態

この「1 画面が取りうる姿」を整理したのが、**UI Stack** という考え方です。Scott Hurff の『Designing Products People Love』で紹介されていて、画面の状態を 5 つに分けます。

| 状態 | いつ起きるか | 描き忘れると |
|---|---|---|
| Ideal（理想） | データが十分にあり、成功した | これがカンプに載る姿 |
| Empty（空） | データがまだない、検索ヒットが 0 | 真っ白で「壊れた？」と思わせる |
| Loading（読み込み中） | データが届くのを待っている間 | 固まったように見える |
| Error（エラー） | 通信やサーバーの失敗 | 無反応で、何が起きたか分からない |
| Partial（部分） | 一部だけ届いた、件数が想定外に多い | レイアウトが崩れる、極端に重くなる |

デザインが描くのは Ideal です。残りの 4 つは絵になっていないので、実装で補います。

手がかりが「うまくいった 1 枚」しかない以上、自分で書いても AI に書かせても、同じように抜けやすい部分です。そして抜けると、そのままバグになります。

## 「空」にも種類がある

5 つの中でも Empty はもう一段分かれます。同じ「空」でも、利用者が置かれた状況が違うからです。

- **初回**: まだ何も作っていない。使い方や最初の一歩を示す
- **検索 0 件**: 探したが見つからない。条件を変える案内を出す
- **全部完了**: やることを全部片づけた。ねぎらいや次の行動を示す

「データがありません」の 1 行で済ませると、この 3 つの違いが消えます。同じ空でも、かける言葉は変わります。

## 状態はかけ算で増える

状態を持つのは画面全体だけではありません。ボタンや入力欄などの部品も、通常・ホバー・フォーカス・押せない・送信中と姿を変えます。

やっかいなのは、画面の状態と部品の状態がかけ算になることです。一覧が Loading の間はボタンも押せない、Error のときは再試行ボタンが出る、というふうに組み合わさります。

だから「数えたつもり」でも抜けが起きます。まず画面の 5 つ、次に主な部品、と分けて数えるのが現実的です。

## 完成の前に状態を数える

つまり「デザイン通りに並んだら完成」ではありません。その画面の UI Stack を一通り数えて、それぞれがどう見えるかを決めて、はじめて実装として完成します。

- この一覧、0 件のときは何が出る？
- 読み込み中は？　通信に失敗したら？
- このボタン、押せないときの見た目は？

AI に画面を作らせたときの確認も、これがそのまま使えます。生成物も Ideal に寄りやすいので、空・読み込み中・エラーが入っているかをこちらが数えて確かめ、抜けていれば「0 件のときとエラーのときも出して」と指示します。

## まとめ

- 画面は 1 枚の絵ではなく、状況で切り替わる状態の集合
- UI Stack はそれを Ideal・Empty・Loading・Error・Partial の 5 つで数える
- 空にも種類があり、部品の状態ともかけ算になるので抜けやすい
- 完成の前に「0 件のとき・失敗のときは？」と 5 つを数える
